# T-001 · 항목 0개 상태에서는 첫 커밋이 통과하지 못한다

- **증상**: 새 프로젝트에 `templates/troubleshooting-system/` 을 복사한 직후 `git commit` 이 `INDEX-CHECK: INVALID (no entries)` / `항목이 하나도 없다` 로 거부됐다. 안내대로 `rebuild-troubleshooting-index.ps1` 을 돌려도 같은 메시지가 나와 빠져나갈 곳이 없었다. 부트스트랩 커밋이라 `git log` 에는 아직 커밋이 하나도 없는 상태였다.
- **원인**: 검사기가 fail-close 라서 "항목 폴더가 비어 있음"을 정상 상태가 아니라 오류로 본다. stale 목차를 막으려는 설계인데, 항목이 아직 없는 신설 시점과 목차가 썩은 상태를 구분하지 않는다. 안내 메시지가 목차 재생성을 시키지만 재생성해도 항목 0개는 그대로라 안내를 따르는 것만으로는 못 벗어난다.
- **해결**: 부트스트랩 커밋에 항목 하나(이 파일)를 포함시킨 뒤 목차를 재생성하고 함께 스테이징했다.
  ```
  powershell -ExecutionPolicy Bypass -File scripts/rebuild-troubleshooting-index.ps1 -HubPath claude-docs/troubleshooting.md
  git add claude-docs/troubleshooting.md claude-docs/troubleshooting/T-001.md
  ```
- **재발방지**: 새 프로젝트에 이 시스템을 배치할 때 **항목 하나를 같이 만든다**. 마침 이 상황 자체가 첫 함정이라 T-001 소재가 된다 — 억지 더미 항목을 만들 필요가 없다. `SETUP.md` 의 설치 절차는 항목 폴더만 만들라고 하고 이 점을 적지 않으므로, 새 프로젝트마다 같은 곳에서 멈추게 된다.
