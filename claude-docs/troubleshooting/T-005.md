# T-005 · 부분 치환이 만든 거짓 생존 (돌연변이 테스트)

- **증상**: `lib/verify.ts` 의 날짜 정규식에 돌연변이 7종을 걸었더니 `[-./년]` → `.` (날짜 구분자를 임의 문자로) 하나만 **생존**했다. 테스트 갭이라 판단해 오탐 케이스 두 건을 추가했는데, 같은 돌연변이를 다시 돌리니 **여전히 생존**했다. 새 테스트가 겨냥한 바로 그 동작인데도 안 죽었다.
- **원인**: 정규식에는 구분자 문자 클래스가 **둘** 있다 — 연↔월 사이의 `[-./년]` 과 월↔일 사이의 `[-./월]`. 치환은 `[-./년]` 만 바꿔서 `[-./월]` 이 그대로 남았고, 남은 쪽이 여전히 "구분자가 있어야 한다"를 강제했다. 그래서 `"2026 8 31"` 같은 입력은 돌연변이 상태에서도 계속 매칭에 실패했다 — **돌연변이가 의도한 만큼 약해지지 않은 것이지, 테스트가 무력했던 게 아니다.**
- **해결**: 두 클래스를 모두 치환하니 곧바로 2건이 실패하며 죽었고, 죽인 것은 새로 추가한 오탐 테스트 두 건이었다.
  ```powershell
  $mutated = $orig.Replace('[-./년]', '.').Replace('[-./월]', '.')
  ```
- **재발방지**: 돌연변이가 생존하면 **테스트 갭을 의심하기 전에 치환이 실제로 의도한 전부에 걸렸는지 본다**. 확인법: ① 치환 전후 문자열이 달라졌는지만 보지 말고 **치환 횟수**를 센다 ② 같은 의미의 토큰이 소스에 여러 번 나오는지 grep 한다. 거짓 생존을 그대로 믿으면 이미 충분한 테스트에 불필요한 케이스를 덧붙이거나, 반대로 "테스트가 원래 약하다"는 잘못된 결론을 내리게 된다.
