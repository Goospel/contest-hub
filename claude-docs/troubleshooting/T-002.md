# T-002 · `npm audit fix --force` 가 Next를 7년 전 버전으로 되돌리려 한다

- **증상**: 스캐폴드 직후 `npm audit` 이 8건(high 4)을 보고했고, 전부 `fix available via npm audit fix --force` 라고 안내했다. 그런데 실제 제안 내용은 `Will install next@9.3.3, which is a breaking change` 와 `Will install drizzle-kit@0.18.1` 이었다. 안내를 그대로 따랐다면 Next 16.2.12를 9.3.3으로, drizzle-kit 0.31을 0.18로 **다운그레이드**할 뻔했다.
- **원인**: `postcss` 와 `sharp` 취약점은 `next` 의 내부 의존성에 있고, `esbuild` 취약점은 `drizzle-kit` 이 끌어오는 `@esbuild-kit/*`(이미 tsx로 통합되어 관리 중단됨) 안에 있다. 둘 다 우리가 직접 선언한 의존성이 아니라 npm이 트리에서 취약 버전을 없앨 방법이 "그 취약 버전을 요구하지 않는 조상 버전까지 내려가기" 밖에 없다. `next` 최신이 이미 16.2.12(= 우리가 쓰는 버전)이므로 위로는 갈 곳이 없어 아래로 제안한 것이다.
- **해결**: 우리가 직접 선언한 `drizzle-orm` 의 high 건(SQL injection via improperly escaped SQL identifiers, GHSA-gpj5-g38j-94v9)만 `0.45.2` 로 올려 해결했다. `drizzle-kit` 도 최신 `0.31.10` 으로 올렸으나 `@esbuild-kit` 경유 경고는 남는다.
  ```
  npm install drizzle-orm@0.45.2
  npm install -D drizzle-kit@0.31.10
  ```
  남은 7건(postcss·sharp·esbuild)은 upstream이 고칠 때까지 그대로 둔다. esbuild 건은 개발 서버에만 해당하고 배포 산출물에는 없다.
- **재발방지**: **이 프로젝트에서 `npm audit fix --force` 를 돌리지 않는다.** `npm audit` 경고가 보이면 먼저 "그게 우리가 직접 선언한 패키지인가"를 본다. 직접 선언한 것이면 해당 패키지만 최신으로 올리고, 전이 의존성이면 제안하는 버전이 다운그레이드인지 확인한다. `fix available` 이라는 문구는 그 fix가 합리적이라는 뜻이 아니다.
